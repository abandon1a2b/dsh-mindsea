# 人员隔离、脑海归属与启用设置

状态：完整设计；v0.3 已实现本机隔离与工作区设置的试用子集，参见 [当前实现边界](../settings-trial.md)。运行时当前仍是共享服务密钥 + X-User-ID，以及插件固定 userId/sessionIds。该方案要替换这些配置，不能将现有实现宣称为多人权限系统。

## 1. 产品模型

**先确定是谁，再确定他使用哪个脑海，最后判断当前会话是否启用。**

工作区决定适用范围，不提供身份或访问权限。角色决定交互方式，不代表一个人。相同目录、相同角色、相同昵称都不能使两个人共享记忆。

| 对象        | 用途                           | 示例                          |
| ----------- | ------------------------------ | ----------------------------- |
| personId    | 真实使用者的稳定内部标识       | 张三；改昵称后不变            |
| identity    | 外部身份与 personId 的可信绑定 | 本机个人 profile / 某平台账号 |
| brainId     | 一个人拥有的独立脑海           | 私人陪伴、工作助手            |
| workspaceId | 注册的工作区，用来匹配启用规则 | 个人聊天目录                  |
| presetId    | 宿主提供的稳定角色标识         | 大肥鱼                        |
| sessionId   | 一次会话及其固定绑定           | 新建/恢复的聊天               |
| audience    | 当前内容会被谁看到             | 本人私聊 / 群聊 / 未知        |

第一版只做**私人脑海**：一个 brain 只属于一个 person，一个 person 可以有多个 brain。不同 brain 默认不交叉检索、归纳或引用。人物画像中的 subjectId 是“谈论的人”，不等于访问者 personId，也不授予这个人物读取权限。

## 2. 人员身份从哪里来

### 本机个人 DSH

首次设置向导提供“创建我的本机身份”，生成不可猜测的 personId，并将该 DSH 安装中的个人 profile 绑定到它。用户只需输入显示名称，不需要手填 ID 或每轮登录。

本机身份的安全边界是操作系统账号和个人 DSH profile。共用同一 OS 账号、同一 profile 的人不能靠昵称获得真正隔离；需切换到各自的已配对 profile，或接入可认证登录。不能声称防得住有权读取同一账户数据库和配置的人。

### 外部聊天桥接

身份键使用 `(connectorId, accountNamespace, externalUserId)`，由已认证的桥接事件提供。昵称、聊天文本“我是张三”、模型参数都不能改变身份。未知账号默认禁用，禁止映射到 local-owner。

跨平台账号合并必须经所有者显式绑定、核验；不能根据同名自动合并。第一版不做自动身份合并。

### 认证而非信任请求头

服务端保存有撤销能力的凭据绑定：credentialId → personId + 允许的 brain + 权限。密钥仅保存安全哈希，浏览器页面不持有服务主密钥。

- 本机配对在 loopback 管理通道完成，管理员批准一次性短期配对码，给该个人 profile 签发受限凭据。
- DSH 服务端代理设置页请求；多人宿主需有自己的登录认证，并传递经核验的身份。
- 运行时凭据不能通过 X-User-ID 任意扮演其他人。身份/brain 冲突直接拒绝。
- 工作区文件、仓库配置、模型工具参数不接收或持久化任何凭据。
- worker 使用任务绑定的 personId/brainId，不允许从模型返回值中选择所有者。

个人凭据与管理员凭据分开。管理能力不能因“能控制某个工作区”而自动获得；记录审计元数据，不记录密钥或对话正文。

## 3. 脑海绑定与跨会话使用

实际隔离键为 `(personId, brainId)`；sessionId、workspaceId、presetId 是上下文属性。

- 张三在工作区 A 使用大肥鱼 → 张三的私人脑海。
- 李四在同一工作区 A 使用同一 preset → 李四自己的脑海或禁用，不能命中张三的脑海。
- 张三的个人脑海和工作脑海不自动合并。
- 同一脑海可以被该所有者显式绑定到多个工作区；移动目录不迁移记忆内容，只修改绑定。

会话首次启用时记录固定 binding：身份、脑海、命中的规则版本、工作区和 preset。后续目录变化不得悄悄切换脑海。

**切换脑海或人员必须新开干净会话。** 旧会话已经注入过的记忆仍在 DSH 上下文里，隐藏工具或改请求参数无法抹掉它。UI 显示“在新会话使用此脑海”，不提供看似安全的原地身份切换。

## 4. 生效规则

规则属于 personId，包含 enabled、brainId 和可选的 workspace / preset / session 条件。一个规则的多个条件使用 AND；避免“角色符合就覆盖了目录限制”。

解析顺序：

1. 人员认证、脑海授权和 audience 检查，任何失败均禁用。
2. 全局/个人暂停开关；强制关闭不可被会话覆盖。
3. 会话显式关闭。
4. 会话显式启用（仅在其既有 binding 内；换脑海需要新会话）。
5. 匹配规则：工作区+角色 → 角色 → 工作区；工作区重叠时精确或更具体路径优先。
6. 同优先级规则指向不同 brain，显示冲突并禁用，不按数据库顺序任选。
7. 无匹配规则：禁用。

高优先级 enable 不能绕过身份和 audience 检查。普通规则的关闭表示该规则命中时关闭；需要“所有范围都关闭”使用个人暂停开关。

工作区由宿主可信 cwd/工作区元数据解析。服务登记 hostId + canonicalRoot：解析符号链接，按真实路径段匹配，避免 `/chat` 错配 `/chat-private`。默认仅目录本身，包含子目录单独勾选。目录不可解析、网络路径不可用或宿主身份不明时不猜测，返回禁用原因。

工作区只是选择条件，不自动导入目录文件。仓库里的配置不能自行打开脑海、修改身份或读取其他人的记忆。

## 5. 群聊和受众

即使已认证的发言人是张三，也不能把张三的私人记忆注入一个别人可见的群聊。**发言者身份和输出受众必须同时检查。**

第一版策略：

| 场景                         | 行为                           |
| ---------------------------- | ------------------------------ |
| 已认证本人、私人 DSH 会话    | 按规则启用                     |
| 已认证平台账号、可信私聊桥接 | 按该人的规则启用               |
| 群聊/多人会话                | 私人脑海禁用                   |
| 来源或受众未知               | 禁用，不回退本机默认身份       |
| 引用/转发另一人的话          | 保留来源，不能当作当前用户事实 |

共享脑海、群组脑海、成员 ACL 与私人信息向群组发布不在第一版范围。以后若支持，应作为独立 brain 类型显式授权，不能复用个人脑海冒充共享空间。

## 6. 一处查看与快速设置

计划在 DSH 设置中提供“脑海”面板，在当前会话提供状态入口。具体 UI 扩展点需在实施时核对目标 DSH 版本；这份设计不声称已有该设置页。

### 首次使用

1. 创建/配对本人身份。
2. 新建脑海或选择本人已有脑海。
3. 点击“仅当前会话启用”或“在当前工作区启用”，可勾选“仅当前角色”。
4. 展示生效预览并保存；只采集启用后的新事件，不自动回放旧聊天。

未认证的人不能从下拉菜单选“张三”就冒充张三。身份切换需要切换已配对 profile/登录身份。

### 面板结构

| 页面       | 内容和操作                                                     |
| ---------- | -------------------------------------------------------------- |
| 总览       | 当前身份、认证来源、全局状态、当前会话脑海与匹配原因           |
| 我的脑海   | 脑海列表、L1/L2/L3 数量、Future 数量、整理积压、最近活动       |
| 生效范围   | 工作区/角色规则、子目录开关、规则冲突、受影响会话预览          |
| 记忆与未来 | 按本人脑海查看、搜索、来源审查、纠正、候选确认和遗忘           |
| 任务与诊断 | 两个队列的状态、失败重试、权限拒绝原因；不显示其他人数据       |
| 人员与配对 | 管理员视图，仅管理身份/凭据/归属元数据；普通人看不到其他人列表 |

快捷设置示意：

```text
脑海
当前身份  张三 · 本机个人 profile 已配对
当前会话  未启用

使用脑海  [ 私人陪伴 ▾ ]    [+ 新建]
生效范围  ( ) 仅当前会话
          (●) 当前工作区
              ~/Chats/companion
              [ ] 包含子目录
              [✓] 仅角色“大肥鱼”

预览：张三在该目录使用大肥鱼时启用。
      其他人员、其他角色、群聊均不启用。

[保存并启用]   [取消]
```

状态必须可解释：未配置 / 未认证 / 已启用 / 手动关闭 / 规则冲突 / 受众不允许 / 服务离线。服务离线仍正常聊天，但不采集到默认脑海或注入旧缓存。

## 7. 关闭、恢复和规则变更

- 禁用会话立即停止新采集、Future 注入和 Memory 工具注册；服务端仍拒绝伪造的工具调用。
- 已持久化且有明确启用授权的任务可继续整理，归属固定，不随会话切换迁移。个人“暂停后台整理”是另一个明确开关。
- 未发送的插件内存缓冲在关闭后丢弃；重新开启不补采关闭期间内容。
- 保存启用时间/DSH 序列游标以及禁用区间，恢复进程后只补采有授权区间内、尚未成功持久化的事件。
- 撤销人员凭据或脑海权限：停止采集与在途模型请求，旧结果提交按授权版本拒绝。已发送到供应商的内容无法追回。
- 新规则不回填旧历史。导入旧历史必须单独操作，预览会话范围、身份与目标脑海。
- 更新规则先展示影响范围；已有会话不自动改 brain，但新的强制关闭/权限撤销立即生效。
- 关闭或撤销后旧模型上下文里已有的资料不会凭空消失，UI 明示新建会话可以避免继续携带旧上下文。

## 8. 服务端数据与 API 边界

新增实体（拟议）：

- persons、external_identities、credentials、credential_brains。
- brains：ownerPersonId、名称、状态、权限版本。
- workspaces：hostId、canonicalRoot、显示路径。
- activation_rules：personId、brainId、条件、enabled、priorityClass、version。
- session_bindings：hostId、sessionId、personId、brainId、audience、bindingVersion、采集游标与启用区间。
- audit_events：操作者、操作、目标 ID、版本和结果，不存记忆正文。

所有 events、records、evidence、dependencies、revisions、Future、两个任务队列、outbox、tombstone、topic/alias 增加 brainId 并保留 ownerPersonId。数据库与事务同时验证复合归属；不能只在 UI 查询加过滤。

- ID 去重包含 brain 边界；同源事件在两个显式授权脑海中的写入互不冲突。
- 查询、来源回读、历史、候选确认、任务列表、重试、重建、遗忘全部按授权 brain 过滤。
- 跨 brain 引用证据和依赖默认拒绝，即使属于同一人。
- Meilisearch 带 personId + brainId 过滤；返回后回 SQLite 重验授权。缓存键包含 person、brain、权限版本。
- 遗忘默认限于当前脑海，不能顺手删除同一个人另一脑海里的副本；跨脑海遗忘是独立显式操作。
- worker 领取任务时和提交结果时都校验权限版本/brain 状态；旧租约不能跨脑海复用。

拟议 API：`/v1/me`、`/v1/brains`、`/v1/activation/rules`、`/v1/activation/resolve`、`/v1/sessions/:id/binding`。resolve 输出 enabled、reason、matchedRuleId、bindingVersion，以及仅在授权后返回的 brain 摘要。不能把 resolve 的缓存结果当成后续请求的永久授权。

管理调用与内容调用使用不同权限。客户端不能传一个 personId 就扩大权限；brainId 参数只表达目标，服务端认证结果决定是否可访问。

## 9. 迁移当前 v0.2.0

当前缺口：固定 userId、sessionIds 为空全部启用、共享密钥可选择任意 X-User-ID、消息 ID 未区分 brain、回放没有启用区间。

迁移必须显式分阶段：

1. 数据迁移：每个旧 userId 创建一个 legacy 私人 brain，保留数据；没有核验所有者前冻结外部访问，不能自动把所有数据归给当前操作者。
2. 管理员在本机逐项映射已核验身份；展示旧数据数量，签发各个人凭据。
3. 更新插件为默认关闭。旧的“全部会话启用”配置不自动生成通配规则，要求设置页选择生效范围。
4. 升级服务与插件一同切换；旧共享密钥模式只允许明确启用的本机单用户兼容期，多人模式禁止。
5. 重建独立索引，验证复合归属、缓存键、任务及撤销流程。迁移事务失败回滚。

## 10. 实施顺序与验收

1. **人员/brain 服务端隔离**：所有数据接口与任务切入同一个授权边界，完成恶意请求测试。
2. **默认关闭和绑定解析**：把采集、整理、工具注册、Future 钩子统一接入启用判断，补生命周期游标。
3. **设置页和会话状态入口**：快速启用、规则预览、冲突说明、查看记忆与任务。页面不暴露服务密钥。
4. **桥接身份/受众适配**：可信账号映射、群聊禁用、未知用户拒绝，不做共享脑海。

验收用例：

- 两个人使用同工作区、同角色、同文本，所有数据仍隔离；改昵称不改变归属。
- 同一个人的两个 brain 不互相检索、引用、重试、重建或遗忘。
- 改 X-User-ID、brainId、任务 ID、来源 ID、缓存命中均不能越权。
- 无规则时零采集、零维护模型调用、零注入、工具不可见也不可执行。
- 禁用期间的历史在恢复/重启后不被补采；新增规则不重放全部旧聊天。
- 群聊中即使发言人身份匹配，也不注入其私人脑海。
- 规则撤销发生在模型推理中时，旧结果不可提交；规则冲突不回退任意脑海。
- symlink、相似路径前缀、远程同名路径不扩大工作区匹配。
- 新身份或新 brain 在新会话启用，不沿用之前已注入私人信息的上下文。

本阶段交付设计，不修改配置、凭据、数据库或用户 DSH profile。
