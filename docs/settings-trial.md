# v0.3 本机设置试用

本版本先交付人员/脑海隔离、默认关闭、工作区匹配和独立本机设置页。它不是设计文档中所有管理功能的最终版本。

## 启动

在项目目录打开两个终端，使用相同的 `MINDSEA_DB`（默认 `data/mindsea.sqlite`）。

```sh
# 终端 A：内容服务
export MINDSEA_API_KEY="$(openssl rand -hex 32)"
npm start

# 终端 B：本机管理页面
npm run settings
```

打开终端 B 打印的 `http://127.0.0.1:4319`，输入该次启动的访问码。页面只绑定本机回环地址；访问码只能登录一次，Cookie 为 HttpOnly / SameSite=Strict，写请求校验 Origin 与 CSRF。结束设置后可 Ctrl+C 关闭管理进程，内容服务继续运行。

服务默认不再接受共享密钥 + 任意 X-User-ID 访问内容。MINDSEA_API_KEY 只保留旧版兼容配置；只有显式 `MINDSEA_LEGACY_ACCESS=1` 才开放旧接口，这个模式不提供多人安全隔离，不要用于试用多人功能。

## 创建和启用

1. 输入人员显示名、脑海名称；也可以为已经创建的人员增加另一个脑海。
2. 创建后默认关闭。选择绝对工作区目录，勾选启用；子目录默认不包含。
3. 展开“查看 DSH 配置位置”，找到自动生成的三个文件：
   - `activation.json`：工作区和启用规则。
   - `dsh-config.json`：填入该个人 DSH profile 的 `mindsea` 插件配置。
   - `start-env.sh`：加载个人凭据的 shell 文件，权限 0600。
4. 在启动 DSH 的终端 `source /absolute/path/start-env.sh`。将 provider/model 改成可用路由，按插件指南安装 `dsh-mindsea-0.3.0.tgz`，新建会话验证。

设置页不会直接改写你的 DSH profile，也不启动或重启 DSH。不要在公开仓库保存这些生成的文件。现有桌面应用需要由能继承该环境变量的启动方式启动；仅在另一个终端 source 不会修改已运行进程的环境。

## 实际边界

- 一份插件配置绑定一个个人 brain；同一个人的其他 brain 也使用独立凭据和配置。
- 凭据只授权指定脑海，服务器根据凭据确定内部数据 namespace，拒绝伪造 X-User-ID / X-Brain-ID。所有原有查询、证据、任务、历史、遗忘路径都使用该隔离 namespace。
- 人员/脑海记录和凭据哈希存入 SQLite schema v4。现有 userId 数据原样保留，不自动归属到新用户，也不会被新凭据访问；旧数据迁移向导尚未实现。
- 当前采用独立 namespace 复用数据表的 user_id 隔离列，尚未将所有表重建为显式 person_id + brain_id 两列。
- 当前个人凭据拥有其单一脑海的内容能力。细分 read/write/admin 权限和外部平台配对尚未实现。
- 会话 ID 在服务端绑定一个 brain；另一个 brain 重用同一 ID 会被拒绝。请在切换人员/brain 时新建会话。
- 工作区来自 DSH session.header.cwd，不从用户文本读取；解析真实路径及 symlink，按路径段匹配，不做字符串前缀匹配。
- `activation.json` 每次判断重新读取。没有匹配规则、文件损坏、目录不存在、受众不为 private 都关闭。
- 这是个人 profile 适配；audience 是管理员配置声明，不会自动识别外部桥接的群聊。禁止把配置声明为 private 后用于多人共享会话。
- 关闭不采集新消息，未发送缓冲会丢弃；本版不自动回放任何旧聊天，因此不补采关闭期间的数据。代价是服务离线/进程崩溃时尚未入库的输入不能靠历史自动恢复。已经入库的任务仍持久化。
- Memory 工具注册到 agent 的作用域；禁用会话不注册，执行也再次检查。动态规则变化后工具可见性在接下来的宿主装配周期刷新。
- 暂停脑海后，服务端拒绝内容请求及在途结果提交。已发往模型的请求不能追回，正在生成的普通回复也可能已经持有旧上下文。

## 本轮不包含

DSH 原生内嵌设置面板、角色/preset 条件、跨平台人员配对、群组脑海、完整 RBAC、历史授权区间补采、旧数据所有者迁移向导和成员审计面板。相关目标仍保留在 `docs/design/identity-and-activation.md`。

## 验证

使用临时 SQLite 数据库浏览器实测了登录、创建脑海、工作区规则保存。自动测试覆盖跨人员/brain 访问拒绝、伪造请求头、暂停/撤销、目录与 symlink 边界、未知受众禁用。官方 DSH 核心运行时测试验证个人凭据下的启用会话可运行，而未启用会话不采集、不调用维护模型、不暴露 Memory 工具。
